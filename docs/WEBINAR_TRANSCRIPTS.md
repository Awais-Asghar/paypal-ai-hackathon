## Key takeaways for this project

**What the judges told us directly**
- "Meaningfully use both PayPal and AI." A PayPal button on an unrelated app is not enough. PayPal must be central to what the project does.
- The five criteria are weighted equally. Presentation is a full fifth of the score, and **Best Demo Delivery is a separate $5,000 prize**. "Don't leave the demo video until the last minute."
- Start from a real problem, then map it onto PayPal capabilities. Don't start from a PayPal product.
- Prize stacking: one Grand Prize *or* one Honorable Mention, plus one Sponsor Prize.
- Existing projects are allowed if meaningfully progressed. Multiple submissions are allowed if substantially different.

**PayPal capabilities they highlighted**
- Payments: Checkout button, payment links, Pay Later (BNPL), Venmo (US-only), Fastlane, Vault.
- Business: Invoicing (including QR codes), Subscriptions, Payouts (multi-sided marketplaces), Disputes, Login with PayPal, Order/Shipment tracking, Transaction Search / reporting.
- Some products (for example **Store Sync** for agentic commerce, and parts of the AI tools) sit behind business review. Too slow for a hackathon, so check before depending on them.
- In-person POS needs physical terminals, so it's out of scope.

**AI tooling**
- **PayPal AI Toolkit** (github.com/paypal/AI-Toolkit) is a coding-agent plugin for Claude Code, Codex and Cursor.
  - Skill: `paypal-best-practices` (auto-loads).
  - Slash commands: `/paypal:setup` (plus `refresh`), `/paypal:sandbox`, `/paypal:test-accounts`, `/paypal:explain-error`, `/paypal:doctor`.
  - It connects to the **sandbox MCP server**: orders and payments, refunds, invoices (create/send/QR), subscriptions, disputes, catalog, shipments, reporting.
- **PayPal Agent Toolkit**, a different thing: tools you embed in *your own* agent. It supports LangChain, CrewAI, Mastra, Vercel AI SDK (TypeScript and Python) and adapts to other frameworks.
- **APIMatic Context Plugin**: PayPal API context for coding agents in 6 languages. It covers the Orders, Payments, Vault, Subscriptions and Transaction Search server SDKs. **Using it during development qualifies you for Best Use of APIMatic** (answer the plugin question on the submission form).
- **AG Studio** (AG Grid): an embedded self-serve dashboard component with the **Studio Agent Framework** (UI, harness, agents, tools). You plug in your own LLM through an adapter. A PayPal + AG Studio boilerplate exists. No license key is needed for judging.

**Sandbox gotchas**
- Access tokens expire after about 8–9 hours. A 401 means it's time for `/paypal:setup refresh`. Cache tokens in app code rather than fetching one per request.
- Client ID is public. Client secret stays server-side only. Keep both in env vars and never commit them.
- Sandbox and live credentials don't cross over. Going live means swapping base URL, client ID and secret.
- Create business (merchant) and personal (buyer) sandbox accounts **in the same country**. Name them, because the name shows up on transactions.
- Turn on **Transaction Search** in the app's settings. Feature toggles take 10–15 minutes to apply.
- Webhooks: expose localhost with ngrok or a Cloudflare tunnel. Subscribe to all events. Return 2xx, or PayPal retries up to 25 times over 3 days. **Verify webhook signatures.** Webhooks belong to one app in one environment.
- Debugging lives in Developer Dashboard → Testing tools / Event logs: sandbox notifications (emails), API calls, webhook events (with a resend button), error logs. Select your app first.
- Test unhappy paths: refunds, declines, failed renewals. Negative testing is available in the sandbox.
- Demo code: github.com/paypal-examples/docs-examples (npm install / npm start in `server/node`).
- Postman: postman.com/paypal has the public API workspace, Braintree, and an **agentic commerce** workspace.
